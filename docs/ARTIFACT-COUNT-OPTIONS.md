# Утверждённая политика количества настоящих артефактов

## Распределения

| Локация | Количество и вероятность | Среднее | Min/max | Ложные области отдельно |
|---|---:|---:|---:|---:|
| Поляна | `3/4/5 = 35/60/5%` | `3.7` | `3..5` | всегда `1` |
| Тёмная лощина | `5/6/7/8/9 = 5/20/47/26/2%` | `7` | `5..9` | `2/3/4 = 33/34/33%` |
| Мёртвый город | `4/5/6/7 = 11/80/7/2%` | `5` | `4..7` | `1/2/3 = 20/60/20%` |

Это окончательно утверждённая пользователем политика. Ранее рассматривавшийся последовательный каскад `3..5 / 5..9 / 4..7` не используется. Типы ложных областей по-прежнему выбираются независимо с весами `enemy/loot/empty = 50/25/25`.

По сравнению со stock `4/8/6` среднее уменьшено до `3.7/7/5`. Тёмная лощина остаётся самой богатой по абсолютному числу, Поляна — самой короткой, Мёртвый город компенсирует меньшее количество более дорогим T2/T3 пулом и высокой опасностью. При активном rescue большая доля созданной добычи становится реально доступной, поэтому сниженные средние также ограничивают рост фактической экономики.

## Реализация

Stock `raid_distribution_anom_zones` — local upvalue `raid_anomalys.spawner_anomals_zones`. Мод не копирует штатную функцию и не меняет исходный GRA Bolt:

1. Находит только именованный upvalue через `debug.getupvalue`.
2. Проверяет тип таблицы, запись уровня, исходное stock-значение и `count_zones`.
3. Проверяет конфиг: одинаковая длина списков, строго возрастающие положительные целые counts, положительные целые веса, сумма ровно 100 и count не выше числа полей.
4. Один раз бросает count и сразу сохраняет plan в state schema 5.
5. Временно меняет одно поле `count_artefacts` через `rawset`, синхронно вызывает оригинал под `pcall` и безусловно восстанавливает прежнее значение до возврата или повторного выброса ошибки.
6. Повторный вызов в том же рейде, включая load/same-level, подавляется сохранённым `spawn_invoked`.

Если безопасный upvalue/API не найден, stock-структура конфликтует либо профиль отсутствует/невалиден, мод не применяет частичный hook и оставляет `4/8/6`. Release-log всегда пишет `artifact_count rolled=... profile=...`, затем сводки `requested/callbacks/created/captured/linked`. Несовпадение получает явный `ERROR ... fail_closed=true`; недостающий предмет или круг не заменяется ложной областью.

Rescue работает с уже созданным exact ID и не вызывает count roll или stock spawner. Unique-ID sets защищают счётчики от повторных callbacks. Число ложных областей рассчитывается прежним независимым кодом.

## Автоматические проверки

`tools/test_artifact_count_policy.py` исполняет production-блок во всех трёх runtime: Lua 5.1, LuaJIT 2.0 и LuaJIT 2.1. Детерминированные выборки по 100000 значений на локацию проверяют точные support/веса/средние; отдельно проверяются сохранение roll без повторного RNG, invalid-config stock fallback, временная подмена и восстановление после success/error, дедупликация ID и неизменность утверждённых decoy-rolls.

Полевой тест остаётся обязательным: проверить release-log, фактические круги и отсутствие повторного spawn после загрузки/перехода внутри той же локации.
