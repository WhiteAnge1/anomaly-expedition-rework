# Исследование фактической реализации

Дата: 2026-10-08. Профиль MO2: `2v2(DX11) (v_6gb) 2.5, Высокие настройки (167)`.

## Владельцы и поток вызовов

- Эффективная расширенная реализация вылазок находится в `GRA Bolt/gamedata/scripts`.
- `z_raid_item_travel_dungeons.script` читает `type_dungeon` из маршрутного листа, телепортирует игрока и на первом обновлении вызывает `raid_tasks_dungeons.issue_task_dungeon(map_used_typ)`. Для `infected` затем синхронно вызывается `raid_anomalys.spawner_anomals_zones(level.name())`.
- `raid_tasks_dungeons.script` выдаёт `raid_general_task_scout_dunge` для `scouting` и `raid_general_task_search_in_treasures_and_delivery_out` для `infected`.
- `raid_tasks_scout_dunge.script` создаёт точки, проверяет 30 м/150 м с биноклем и выдаёт `raid_intelligence_note`. Эта логика не заменяется.
- `raid_tasks_search_treasures_delivery.script` в стадии 0 делает до десяти попыток `treasure_manager.get_random_stash`, отмечает найденный контейнер `secondary_task_location` и завершает задачу только после возвращения домой. Альфа подавляет именно эти десять вызовов, оставляя задачу выхода рабочей.
- `raid_anomalys.script`: `spawner_anomals_zones` создаёт динамические рейдовые зоны и вызывает `spawn_artefact_in_zone`; функция возвращает точный server ID. Это минимальная и надёжная граница источника №3 из ТЗ.
- `raid_artefacts.script` отдельно оборачивает рейдовый спавн для рандомизации параметров. Наш файл имеет префикс `zzz_`, поэтому оборачивает уже совместимую цепочку и сохраняет её результат.

## Артефактные награды контейнера

- Авторитетная таблица `raid_artefacts.raid_artefacts_tiers_by_dop` содержит всю фактическую номенклатуру текущей сборки: группы 1–4 помечены кодом как `junk art`, 5–8 — как `normal art`.
- Для вылазок используется соответствие: T1 = группы 1–5 (весь мусор + T1), T2 = 5–6 (T1 + T2), T3 = 6–7 (T2 + T3). Группа 8 в эти три локации намеренно не включена.
- В исследованной версии таблицы это 103 различных секции для T1 и по 106 для T2/T3; дубликатов внутри исходных групп нет.
- Списки читаются во время выполнения, поэтому новые артефакты, добавленные в эти штатные группы РВМ, автоматически попадают в награды без обновления нашего конфига.
- После `alife_create_item` объект передаётся `raid_artefacts.addToQueuedArtefacts`. Штатная очередь сериализуется как `m_data.raid_artefacts_queued_artefacts`, переживает сохранение/загрузку и при выходе объекта online вызывает `getRandomArtefactTier`/`randomizeArtefact`.
- Вызов очереди защищён `pcall`. Если API отсутствует или выбрасывает ошибку, нерандомизированный артефакт удаляется, а подробная причина пишется в лог вместо сохранения поломанной награды.
- Фактическое распределение класса в РВМ: 40/33/15/8/4% для классов 1–5, но `getRandomArtefactTier` соблюдает внутренний максимум конкретной группы. Мутации и дополнительные свойства назначаются тем же `randomizeArtefact`, а не дублируются модом.

## Разделение источников артефактов

- Система аномалий Arrival создаёт артефакты через `drx_da_main.spawn_artefact_on_smart` (`drx_da_main.script`, около строк 1450–1594).
- GRA Bolt сам различает этот путь и `raid_anomalys.spawn_artefact_in_zone` в `raid_artefacts.script`.
- Новый мод не перебирает все артефакты уровня и не оборачивает систему аномалий Arrival. В области попадают только ID, возвращённые рейдовым спавнером.

## Карта и PAW

- PAW добавляет map spots через `modxml_map_spots_paw.script`, а контекстное меню получает ID выбранного server object (`map_spot_menu_add_property`).
- PAW предоставляет `generate_scripted_mapspot_at`, `set_pingspot_persistence` и `deregister_script_zone`. Мод создаёт отдельную невидимую `script_zone`, делает её постоянной на срок жизни области и освобождает тем же API.
- Поэтому круг прикреплён не к артефакту и не к физическому `raid_shelter_gag`, а к отдельному якорю в смещённом центре. PAW видит только `script_zone`; это устраняет ложное действие перехода в контекстном меню.
- Собственные `map_spots.xml` не копируются: DXML включает маленький фрагмент `map_spots_rvm_sorties.xml`, совместимый с PAW.

## A-Life, callbacks и сохранения

- Доступны callbacks `actor_on_item_take` и `npc_on_item_take`; второй уже используется UI сборки и передаёт `(npc, obj)`.
- Состояние хранится в `m_data.rvm_sorties_rework`: ID артефактов, якорей, boxes, созданных мутантов, флаги и счётчики.
- Повторная загрузка не запускает генерацию: сохранены таблица `artifact_zone` и `decoys_created`. `on_before_level_changing` только помечает незавершённый переход; на `actor_on_first_update` мод сравнивает фактический уровень и доступное состояние RVM. При same-level reload/fast travel зоны сохраняются и spots восстанавливаются, при подтверждённом уходе выполняется очистка.
- `actor_on_item_take` не гарантирован для предмета, снятого с трупа. Для каждой открытой artifact-zone теперь дополнительно проверяется только точный `artifact_id`: фактический actor inventory, online-parent и защищённая цепочка server `parent_id` (в этой сборке actor имеет ID `0`, свободный предмет — sentinel `65535`). Ошибка API оставляет область открытой и один раз диагностируется.
- Дистанционный подбор артефакта NPC может удалить исходный world-object и создать в инвентаре NPC новый объект той же секции с другим ID. При последующем `actor_on_item_take` lineage восстанавливается только если старый exact ID уже отсутствует и среди открытых зон существует ровно один кандидат той же секции; неоднозначность fail-closed оставляет зоны открытыми.
- Debug-диагностика артефакта сообщает наличие server/online object, обе позиции, parent/parent-chain, расстояние и перепад высоты до центра области и ближайшей level-vertex. Это позволяет доказать провал под карту без точной метки артефакта и без вмешательства в штатный spawn.
- Очередь ещё не вышедших online редких артефактов контейнера сохраняет сам `raid_artefacts`; мод не заводит конкурирующее хранилище классов или мутаций.
- После подтверждённой смены уровня выполняется идемпотентная очистка. Это исключает преждевременное удаление зон на внутренних переходах. Освобождение отсутствующего объекта защищено проверкой `alife_object(id)`.

## Debug UI

- Фактический `_g.script` сборки реализует `add_console_command(name, f)` через таблицу `debug_cmd_list.command_get_list()`; это не регистрация команды обычной движковой консоли `~`.
- `ui_debug_main.script` вызывает командный слой как `debug_cmd_list.command_give(wrd, output, self, p)`, где `output` — текст аргументов, `self` — экземпляр Debug UI с методом `SendOutput`, `p` — разобранные значения.
- Callback мода не полагается на жёсткую позицию UI-аргумента: он безопасно ищет объект с `SendOutput` среди полученных значений, вызывает метод через `pcall` и всегда сохраняет `printf`-дубликат. Неизвестная сигнатура поэтому не должна уронить игру.

## Радиусы и уровни

- Фактические ID: Поляна — `y04_pole` (T1), Тёмная лощина — `k01_darkscape` (T2), Мёртвый город — `l09_deadcity` (T3).
- Штатная таблица активного `GRA Bolt` задаёт количество артефактов по локации, не по тиру: `y04_pole=4`, `k01_darkscape=8`, `l06_rostok=3`, `l08_yantar=3`, `l09_deadcity=6`. Реворк поддерживает Поляну/Тёмную лощину/Мёртвый город и обязан сохранять их числа `4/8/6`; обычные полевые проверки должны различать эти counts.
- `raid_dospawn_dungeons.raid_sim_dospawn[level][type].spawn_block_radius`: Поляна 50, Лощина 100, Мёртвый город 60. Альфа читает эти значения напрямую и добавляет `ambush_extra_padding`; при отсутствии пишет диагностическое сообщение и использует fallback.
- Исходник OpenXRay подтверждает формулу `originSize × clamp(GlobalMap current zoom, scale_min, scale_max)`. После полевого сравнения T1/T3 оставлены `32/48 px`, а только T2 увеличен `40→60 px`; zoom `1..4.5` не менялся. Старые имена сохранены как aliases для тестовых сохранений.
- Для `start` центр опасной области сначала ищется не ближе 120 м от старта, затем ограничение ослабляется до локального `enemy_spawn_distance_min` (90 м Поляна, 80 м Мёртвый город). Старое требование вынести сам центр за полный порог активации `radius + padding + margin` создавало практически недостижимые 205–235 м и удалено; безопасность членов squad по отношению к actor, кругу, level vertex и аномалиям не ослаблена. Для `proximity` Тёмной лощины сохраняются zone-ring и ограниченный actor-ring `120..170` м с реальным `device().cam_dir`. Найден дефект старого фильтра: он собирал `IsAnomaly` со всех ALife-уровней, поэтому совпадающие X/Z других карт могли заблокировать все точки Поляны. Новый сбор повторяет штатную семантику RVM и принимает только текущий `game_vertex` level; расстояние считается от края прочитанной sphere shape, а неизвестная/box shape получает консервативный радиус. При исчерпании вариантов область остаётся armed и делает редкую повторную попытку вместо закрытия как пустышки или дальнего ложного spawn.
- Утверждена гибридная политика: `start` для Поляны и Мёртвого города, `proximity` для Тёмной лощины. Фактический start-spawn выполняется в том же actor update сразу после того, как штатный спавн артефактов завершился и decoy plan создал enemy-зону; к этому моменту `start_pos` уже зафиксирована. Для `start` camera-check намеренно не является допуском, зато обязательны нахождение внутри отмеченного круга, level vertex, профильная дистанция и от текущего actor, и от сохранённого старта, край аномальной shape и разнесение существ. Для `proximity` используется реальный `device().cam_dir` и прежний actor fallback. `zone.triggered` и `spawned_ids` сохраняются, поэтому load не повторяет успешный spawn. Если безопасный start невозможен или anomaly scan неполон, зона остаётся armed и повторяет только внутренний поиск.
- После начала вылазки физика X-Ray может столкнуть или скатить артефакт за исходную приблизительную область, в том числе за доступную часть карты. Повторно наблюдавшееся сильное скатывание «Души» относится именно к южному склону Поляны (`y04_pole`, dxz примерно 42→129); переносить это ограничение на Лощину или Мёртвый город без проверки нельзя. Это объясняет последующее перемещение, но не артефакт, который уже на первом кадре находится вне окружности.
- Exact loot/artifact используют собственные wrapper spots `rvm_exact_loot_icon` и `rvm_exact_artifact_icon` с теми же проверенными PAW-текстурами, но с `location_level=20`. Это позволяет поднять иконку в сортировке, не переопределяя исходный PAW XML. Старые spot IDs удаляются при refresh для совместимости сохранений.
- Маркер прикреплён к exact object ID и удаляется при закрытии области. В debug он получает технический текст; пользовательский режим передаёт локализованную нетехническую подсказку без ID и координат.

## Нативные отряды опасных областей

- Штатный `SIMBOARD:create_squad(smart, section)` создаёт `online_offline_group` на позиции smart terrain, поэтому для точной координаты внутри области используется модель базового `create_squad_at_named_location`: `alife_create(group_section, pos, lvid, gvid)`, затем `squad:create_npc(nil, pos, lvid, gvid)`, `SIMBOARD:setup_squad_and_group` и `squad_on_npc_creation` для каждого члена.
- Командир является состоянием server group и читается через `squad:commander_id()`. Базовый `sim_squad_scripted:show()` переносит map spot при изменении этого ID; exact enemy-marker реворка повторяет ту же семантику, но использует собственную иконку и не отмечает каждый member.
- 57 собственных секций наследуют `online_offline_group` и содержат только фиксированный `npc`, без `npc_random`. Runtime сравнивает фактический multiset секций с preset; несовпадение, ошибка создания или callback приводят к освобождению всей группы и следующей попытке каскада.
- Выбор двухступенчатый: категория `frequent/rare/superrare` с относительными весами `4:2:1`, затем равновероятный preset внутри категории. Таблицы намеренно могут быть сильнее среднего спавна RVM, поскольку сама опасная область заранее видна игроку.
- Save-state хранит `squad_id`, preset/category, точные member IDs/sections, ступень каскада и marker target. На загрузке группа и её члены переоткрываются через ALife. Iterator member не получает прямого `member:alive()`; применяется защищённый `safe_alive` к повторно найденному server/online object.
- Cleanup освобождает существующую группу одним `alife_release(squad)`. Сохранённые member IDs используются только как защитный orphan fallback, если server group уже отсутствует либо group release завершился ошибкой.
- Map XML поддерживает `location_level`, а changelog текущих modded exes подтверждает сортировку map spots по нему. Собственные exact-иконки получают уровень 20 против обычных кругов без повышенного уровня. Проверка всех 11 фактических `map_spots*.xml` показала только обычные `width/height` и не выявила отдельного hit-area/click-area; Lua API также не гарантирует cursor hit-test priority. Поэтому artifact/loot level-map icons увеличены с `12×12` до `14×14`, enemy — с `11×11` до `15×15`, без смещения точных координат. Нормальный tooltip круга всегда сохранён.
- Пользовательские `show_exact_*` независимы и по умолчанию выключены. Вне debug они передают `""` в `map_add_object_spot_ser`, то есть icon-only без имени/подписи/ID/координат. Полный технический текст существует только в debug. Idempotent add/remove сохраняется после load.
- Для живого `squad:commander_id()` используется собственный wrapper `rvm_exact_enemy_icon` с проверенной GRA-текстурой красного squad leader, увеличенной до `15×15` без pointer. Старый `alife_presentation_squad_enemy_1` снимается при refresh для совместимости тестовых сохранений. `crlc_squad_red` не выбран, потому что его wrapper содержит `quest_pointer`. Штатные RVM squad/NPC не перебираются и не маркируются.
- Loot использует четыре этапа medicine/valuable/ordinary/rare; принятая щедрость и равномерное число ordinary-rolls не изменены. После полевой калибровки центр строится вокруг ящика со смещением не более `radius/3` на T1, `radius/5` на T2 и `radius/10` на T3; делитель конфигурируется по иерархии профилей. T2/T3 будут просмотрены ещё раз в финальных обычных рейдах без debug.
- Неудачная привязка artifact-центра не удаляет ID из `pending_artifacts`: безопасные попытки продолжаются каждое обновление. Первый отказ за сессию/загрузку остаётся явным `ERROR`, одинаковые повторы подавляются, а debug не чаще раза в 60 секунд пишет один summary со счётчиком. Успешная привязка очищает rate-limit state; это не rescue и не признание объекта обработанным.
- Два T2-прогона после сжатия offset дали `5/8` и `7/8` областей при восьми захваченных артефактах. Провалившиеся ID часто делили штатную anomaly-zone с успешными ID; старый лог не сохранял причину отдельной попытки, поэтому точную ретроспективную атрибуцию сделать нельзя, но общий `zone_separation_min=45` являлся доказанным условием отказа. Истинные artifact-центры теперь игнорируют только уже существующие истинные artifact-зоны; ложные зоны продолжают блокировать близкое размещение. Следующий отказ записывает исходную позицию, near-origin и агрегированные причины всех попыток.
- Artifact-offset также переведён на профили: T1 `0.35..0.80` сохранён, T2 ограничен `0.10..0.20`, T3 — `0.06..0.12`. В отличие от прежнего варианта, после nav snapping проверяется фактический offset относительно исходной позиции артефакта. Это не rescue: артефакт не перемещается, а `(0,0,0)`/underground остаются диагностируемыми отдельно.
- Базовый `raid_anomalys.spawn_artefact_in_zone` после `shift_vector_for_artefacts` действительно не проверяет второй `level.vertex_id` на invalid перед `level.vertex_position` и create. Это соответствует полевым strict-origin объектам с initial LVID `4294967295`. Rework синхронно защищает environment исходной RVM-функции, bounded-повторами требует valid vertex/static-ray/captured-field и затем возвращается в штатную `raid_artefacts`-обёртку, сохраняя `addToQueuedArtefacts`. Для старых save обнаружен более сильный источник provenance: публичный `raid_anomalys.save_state` выдаёт local `raid_current_anomaly_zones`, где запись поля содержит `artefact_id`, `pos`, `size_zone`, `anom_zone`, а ключом служит исходный LVID. Поэтому schema-2/3 origin recovery больше не доверяет X/Z-снапу или нашей linked area: допускается только unique registry match; ambiguous/missing/mismatch fail-closed.
- Координатная эвристика границ игровой карты намеренно не добавляется: доступная область не представлена надёжной общей Lua-границей, а ручные bounding boxes для каждой локации хрупки и способны переместить корректный предмет. Следствие принято как известное редкое ограничение: артефакт может физически оказаться за доступной частью карты, но оставаться внутри связанного круга и потому не соответствовать ни `origin_mismatch`, ни `underground`, ни `rolling`. Когда он устойчиво выйдет дальше `linked radius + 5 м` на 15 секунд, существующий rolling-классификатор сможет применить выбранную production policy; до этого автоматического rescue нет.

## Переопределения и конфликты

- `gamedata/configs/mod_system_rvm_sorties_rework.ltx`: DLTX-переопределяет только `description` шести маршрутных листов, чтобы убрать безусловное упоминание тайника.
- `gamedata/scripts/modxml_rvm_sorties_map_spots.script`: DXML-вставка, без замены картографических XML сборки.
- Остальные файлы имеют уникальные имена. Полных копий Lua РВМ, системы аномалий Arrival или PAW нет.
