# Исследование фактической реализации

Дата: 2026-10-08. Профиль MO2: `2v2(DX11) (v_6gb) 2.5, Высокие настройки (167)`.

## Владельцы и поток вызовов

- Эффективная расширенная реализация вылазок находится в `GRA Bolt/gamedata/scripts`.
- `z_raid_item_travel_dungeons.script` читает `type_dungeon` из маршрутного листа, телепортирует игрока и на первом обновлении вызывает `raid_tasks_dungeons.issue_task_dungeon(map_used_typ)`. Для `infected` затем синхронно вызывается `raid_anomalys.spawner_anomals_zones(level.name())`.
- `raid_tasks_dungeons.script` выдаёт `raid_general_task_scout_dunge` для `scouting` и `raid_general_task_search_in_treasures_and_delivery_out` для `infected`.
- `raid_tasks_scout_dunge.script` создаёт точки, проверяет 30 м/150 м с биноклем и выдаёт `raid_intelligence_note`. Эта логика не заменяется.
- `raid_tasks_search_treasures_delivery.script` в стадии 0 делает до десяти попыток `treasure_manager.get_random_stash`, отмечает найденный контейнер `secondary_task_location` и завершает задачу только после возвращения домой. Альфа подавляет именно эти десять вызовов, оставляя задачу выхода рабочей.
- `raid_anomalys.script`: `spawner_anomals_zones` создаёт динамические рейдовые зоны и вызывает `spawn_artefact_in_zone`; функция возвращает точный server ID. Это минимальная и надёжная граница источника №3 из ТЗ.
- `raid_artefacts.script` отдельно оборачивает рейдовый спавн для рандомизации параметров. Наш файл имеет префикс `zzz_`, поэтому оборачивает уже совместимую цепочку и сохраняет её результат.

## Артефактные награды контейнера

- Авторитетная таблица `raid_artefacts.raid_artefacts_tiers_by_dop` содержит всю фактическую номенклатуру текущей сборки: группы 1–4 помечены кодом как `junk art`, 5–8 — как `normal art`.
- Для вылазок используется соответствие: T1 = группы 1–5 (весь мусор + T1), T2 = 5–6 (T1 + T2), T3 = 6–7 (T2 + T3). Группа 8 в эти три локации намеренно не включена.
- В исследованной версии таблицы это 103 различных секции для T1 и по 106 для T2/T3; дубликатов внутри исходных групп нет.
- Списки читаются во время выполнения, поэтому новые артефакты, добавленные в эти штатные группы РВМ, автоматически попадают в награды без обновления нашего конфига.
- После `alife_create_item` объект передаётся `raid_artefacts.addToQueuedArtefacts`. Штатная очередь сериализуется как `m_data.raid_artefacts_queued_artefacts`, переживает сохранение/загрузку и при выходе объекта online вызывает `getRandomArtefactTier`/`randomizeArtefact`.
- Вызов очереди защищён `pcall`. Если API отсутствует или выбрасывает ошибку, нерандомизированный артефакт удаляется, а подробная причина пишется в лог вместо сохранения поломанной награды.
- Фактическое распределение класса в РВМ: 40/33/15/8/4% для классов 1–5, но `getRandomArtefactTier` соблюдает внутренний максимум конкретной группы. Мутации и дополнительные свойства назначаются тем же `randomizeArtefact`, а не дублируются модом.

## Разделение источников артефактов

- Система аномалий Arrival создаёт артефакты через `drx_da_main.spawn_artefact_on_smart` (`drx_da_main.script`, около строк 1450–1594).
- GRA Bolt сам различает этот путь и `raid_anomalys.spawn_artefact_in_zone` в `raid_artefacts.script`.
- Новый мод не перебирает все артефакты уровня и не оборачивает систему аномалий Arrival. В области попадают только ID, возвращённые рейдовым спавнером.

## Карта и PAW

- PAW добавляет map spots через `modxml_map_spots_paw.script`, а контекстное меню получает ID выбранного server object (`map_spot_menu_add_property`).
- PAW предоставляет `generate_scripted_mapspot_at`, `set_pingspot_persistence` и `deregister_script_zone`. Мод создаёт отдельную невидимую `script_zone`, делает её постоянной на срок жизни области и освобождает тем же API.
- Поэтому круг прикреплён не к артефакту и не к физическому `raid_shelter_gag`, а к отдельному якорю в смещённом центре. PAW видит только `script_zone`; это устраняет ложное действие перехода в контекстном меню.
- Собственные `map_spots.xml` не копируются: DXML включает маленький фрагмент `map_spots_rvm_sorties.xml`, совместимый с PAW.

## A-Life, callbacks и сохранения

- Доступны callbacks `actor_on_item_take` и `npc_on_item_take`; второй уже используется UI сборки и передаёт `(npc, obj)`.
- Состояние хранится в `m_data.rvm_sorties_rework`: ID артефактов, якорей, boxes, созданных мутантов, флаги и счётчики.
- Повторная загрузка не запускает генерацию: сохранены таблица `artifact_zone` и `decoys_created`. `on_before_level_changing` только помечает незавершённый переход; на `actor_on_first_update` мод сравнивает фактический уровень и доступное состояние RVM. При same-level reload/fast travel зоны сохраняются и spots восстанавливаются, при подтверждённом уходе выполняется очистка.
- `actor_on_item_take` не гарантирован для предмета, снятого с трупа. Для каждой открытой artifact-zone теперь дополнительно проверяется только точный `artifact_id`: фактический actor inventory, online-parent и защищённая цепочка server `parent_id` (в этой сборке actor имеет ID `0`, свободный предмет — sentinel `65535`). Ошибка API оставляет область открытой и один раз диагностируется.
- Дистанционный подбор артефакта NPC может удалить исходный world-object и создать в инвентаре NPC новый объект той же секции с другим ID. При последующем `actor_on_item_take` lineage восстанавливается только если старый exact ID уже отсутствует и среди открытых зон существует ровно один кандидат той же секции; неоднозначность fail-closed оставляет зоны открытыми.
- Debug-диагностика артефакта сообщает наличие server/online object, обе позиции, parent/parent-chain, расстояние и перепад высоты до центра области и ближайшей level-vertex. Это позволяет доказать провал под карту без точной метки артефакта и без вмешательства в штатный spawn.
- Очередь ещё не вышедших online редких артефактов контейнера сохраняет сам `raid_artefacts`; мод не заводит конкурирующее хранилище классов или мутаций.
- После подтверждённой смены уровня выполняется идемпотентная очистка. Это исключает преждевременное удаление зон на внутренних переходах. Освобождение отсутствующего объекта защищено проверкой `alife_object(id)`.

## Debug UI

- Фактический `_g.script` сборки реализует `add_console_command(name, f)` через таблицу `debug_cmd_list.command_get_list()`; это не регистрация команды обычной движковой консоли `~`.
- `ui_debug_main.script` вызывает командный слой как `debug_cmd_list.command_give(wrd, output, self, p)`, где `output` — текст аргументов, `self` — экземпляр Debug UI с методом `SendOutput`, `p` — разобранные значения.
- Callback мода не полагается на жёсткую позицию UI-аргумента: он безопасно ищет объект с `SendOutput` среди полученных значений, вызывает метод через `pcall` и всегда сохраняет `printf`-дубликат. Неизвестная сигнатура поэтому не должна уронить игру.

## Радиусы и уровни

- Фактические ID: Поляна — `y04_pole` (T1), Тёмная лощина — `k01_darkscape` (T2), Мёртвый город — `l09_deadcity` (T3).
- `raid_dospawn_dungeons.raid_sim_dospawn[level][type].spawn_block_radius`: Поляна 50, Лощина 100, Мёртвый город 60. Альфа читает эти значения напрямую и добавляет `ambush_extra_padding`; при отсутствии пишет диагностическое сообщение и использует fallback.
- Полевые тесты показали сначала чрезмерный рост, затем недостаточный охват: linked artifact с фактическим смещением 58.3 м визуально оказался за кругом радиуса 79 м. Логический радиус отделён от UI-пикселей; текущая калибровка использует базы 64/80/96 px, `scale_min=1`, `scale_max=2.25`, alpha 220. На общем плане круги компактнее варианта 80/96/112, на близком — примерно на треть крупнее. Старые имена оставлены как aliases для тестовых сохранений.
- Опасные ложные области размещаются не ближе полного порога активации (`radius + ambush_trigger_padding + margin`) от стартовой позиции. При активации поиск точки появления имеет строгий и ослабленный режимы, но оба требуют штатную дистанцию до actor, положение вне направления взгляда и зазор от известных аномалий. Видимый fallback намеренно запрещён; при исчерпании безопасных вариантов область закрывается без существ.
- Точная цель loot использует уже существующий PAW spot `paw_stash_red`; отдельная текстура не добавляется. В полном debug её tooltip технический, в пользовательском режиме — нейтральный.
- Точный linked artifact использует существующий PAW spot `paw_stash_green` из `[Интерфейс] Personal Adjustable Waypoint/gamedata/configs/ui/map_spots_paw.xml` (зелёный stash 12×12). Маркер прикреплён к exact artifact ID и удаляется при закрытии области или отключении обоих режимов показа.
- Пользовательские `show_exact_artifact_markers`, `show_exact_loot_markers`, `show_exact_enemy_markers` независимы от полного debug и по умолчанию выключены. Они переиспользуют те же idempotent add/remove-пути, поэтому не создают отдельного сохраняемого состояния: после load метки восстанавливаются, а повторный callback не должен дублировать spot. Debug имеет приоритет только над текстом tooltip и показывает технические данные.
- Для живых `zone.spawned_ids` используется существующий GRA Bolt spot `alife_presentation_squad_enemy_1` из `gamedata/configs/ui/map_spots.xml` и `map_spots_16.xml`: обычный красный squad leader 11×11 без pointer. `crlc_squad_red` не выбран, потому что его wrapper содержит `quest_pointer`. Штатные RVM squad/NPC не перебираются и не маркируются.
- Старое наполнение loot почти равноправно выбирало utility/modules (`45/55`). Новый алгоритм сохраняет обычный target `1..6`, но дорогие предметы берёт только из явного `loot_valuable` текущего тира с квотой `35% → 10% → 1.5%`; medicine и остальные валидные секции образуют low-value fill. Исчерпание дешёвого distinct pool завершает заполнение, а не форсирует дорогую секцию. Rare slot остаётся независимым.

## Переопределения и конфликты

- `gamedata/configs/mod_system_rvm_sorties_rework.ltx`: DLTX-переопределяет только `description` шести маршрутных листов, чтобы убрать безусловное упоминание тайника.
- `gamedata/scripts/modxml_rvm_sorties_map_spots.script`: DXML-вставка, без замены картографических XML сборки.
- Остальные файлы имеют уникальные имена. Полных копий Lua РВМ, системы аномалий Arrival или PAW нет.
