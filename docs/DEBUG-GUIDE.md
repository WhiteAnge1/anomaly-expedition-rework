# Диагностика и тестовый режим

Это руководство предназначено для тестировщиков и разработчиков **Anomaly Expedition Rework**. Для обычной игры менять описанные здесь параметры не требуется.

Все строки мода в журнале начинаются с `[Anomaly Expedition Rework]`. Основной конфиг находится в `gamedata/configs/plugins/rvm_sorties_rework.ltx` внутри установленного MO2-мода.

## Обычному пользователю

Для обычной игры оставьте `debug_mode = auto`, все `debug_force_*` выключенными, `debug_cleanup_current_sortie = false` и не запускайте watcher. Это сохраняет нормальный случайный баланс и не добавляет на карту технические ID/координаты. Если нужны только точные подсказки на карте, используйте независимые `show_exact_*` из соответствующего раздела ниже: они не включают полный debug.

Остальные разделы нужны для воспроизводимого полевого теста, сбора отчёта об ошибке или разработки.

## Перед началом

1. Полностью закройте X-Ray.
2. Сохраните копию текущего `rvm_sorties_rework.ltx` либо запишите изменяемые значения.
3. Меняйте параметры только в секции `[global]`, если тест не требует иного.
4. После правки LTX полностью запустите игру заново. Перезагрузка сохранения не гарантирует перечитывание конфига.
5. Для нового сценария войдите в новую аномальную экспедицию. Маршрутный лист — только пропуск; области создаются при фактическом входе на локацию экспедиции.

## `debug_mode`: постоянный режим из конфига

```ini
debug_mode = auto
```

- `auto` — штатное публичное значение. Полный debug включается, только если сборка запущена с глобальным `DEV_DEBUG = true` или `DEV_DEBUG_DEV = true`.
- `on` — принудительно включает подробный журнал, технические tooltip областей, все exact-маркеры и автоматический census независимо от глобальных debug-флагов.
- `off` — принудительно выключает полный debug, даже если глобальный debug сборки включён.

Устаревший `debug_log` используется только как fallback, если строка `debug_mode` отсутствует. В актуальном конфиге управляйте только `debug_mode`.

Debug не включает и не выключает создание областей, наград или противников. Он меняет только диагностику и отображение технических данных.

## Временное переключение во время игры

Runtime-команды доступны в **Debug UI debug launcher**, а не в обычной консоли X-Ray по клавише `~`. Они регистрируются только при `DEV_DEBUG = true` или `DEV_DEBUG_DEV = true`:

```text
rvm_rework_debug_on
rvm_rework_debug_off
rvm_rework_debug_auto
rvm_rework_census
```

Первые три команды временно переопределяют `debug_mode`. В ответ Debug UI показывает строку вида:

```text
runtime debug mode=on effective=true DEV_DEBUG=true DEV_DEBUG_DEV=false
```

`mode` — выбранный runtime-режим, `effective` — фактическое состояние полного debug. `auto` снимает временное переопределение и снова следует LTX и глобальным debug-флагам.

Дополнительная форма `rvm_rework_debug auto|on|off` поддерживается, но команды без аргументов надёжнее для разных вариантов launcher. Если UI не передал объект окна в callback, ответ всё равно записывается в `xray_*.log`.

Runtime override не сохраняется как настройка: он сбрасывается при callback перехода/перезагрузки уровня и после полного перезапуска игры. После save/load или fast travel при необходимости включите его повторно.

## Что появляется при полном debug

Обычное описание приблизительного круга сохраняется. Ниже добавляется технический tooltip с типом области (`artifact`, `enemy`, `loot`, `empty`), anchor ID, логическим радиусом и связанным object/squad ID.

Также показываются все точные метки:

- зелёная — связанный рейдовый артефакт;
- красная stash-иконка — loot-контейнер;
- красная squad-иконка — живой командир отряда, созданного модом.

Точная loot-метка привязана к visual/box, а не к центру приблизительного круга. Она снимается при открытии контейнера. Enemy-метка переносится на следующего живого участника отряда после смерти командира и исчезает после гибели последнего. Artifact-метка снимается при штатном закрытии связанной области.

## Пользовательские exact-маркеры без полного debug

Три параметра включаются независимо:

```ini
show_exact_artifact_markers = false
show_exact_loot_markers = false
show_exact_enemy_markers = false
```

При `debug_mode = off` значение `true` показывает только выбранную категорию точных меток. Такой казуальный режим использует короткую локализованную подсказку, но не включает технические tooltip, ID, координаты, содержимое, подробный журнал или census. Пустой tooltip намеренно не используется: X-Ray показывает его как буквальное `no hint`. Полный debug имеет приоритет и показывает все три категории независимо от этих значений.

Для проверки включайте параметры по одному. После save/load метка должна восстановиться без дубля, а pickup/open/death/cleanup — удалить её. После теста верните все три значения в `false`, если игрок не хочет использовать эту подсказку постоянно.

## Census населения

Команда `rvm_rework_census` ничего не создаёт и не удаляет. В Debug UI она выводит краткий итог:

```text
census squads=N stalkers=N mutants=N (details in xray log)
```

Подробности в `xray_*.log` ограничены текущим уровнем и заключены между `census begin` и `census end`. Для squad и участников указываются section/ID, безопасно определённый статус жизни и `owned_by_rework`.

- `owned_by_rework=true` означает, что объект или отряд создан именно этим модом.
- `owned_by_rework=false` означает штатное население RVM/других систем; мод не должен забирать его в свой cleanup.
- `alive=unknown` допустим для server-объекта, если X-Ray не дал безопасного способа прочитать состояние. Это не считается живым или мёртвым принудительно.

Census — диагностическая функция и работает fail-closed. Если хрупкий объект X-Ray вызывает исключение, мод один раз пишет:

```text
[Anomaly Expedition Rework] ERROR census disabled context=... error=...
```

После этого только census отключается до перезапуска игры. Загрузка, вылазка и основная логика мода обязаны продолжиться. Повторяющийся spam этой ошибки или FATAL — дефект, для которого нужен полный лог.

## Принудительные тестовые параметры

Эти параметры нарушают обычную случайность и не предназначены для постоянной игры:

```ini
debug_force_decoy_type = off
debug_force_tier = 0
debug_cleanup_current_sortie = false
```

### `debug_force_decoy_type`

- `off` — штатный взвешенный выбор;
- `artifact` — оставить только настоящие артефактные области, без ложных;
- `enemy` — принудительно создавать опасные ложные области;
- `loot` — принудительно создавать loot-области;
- `empty` — принудительно создавать пустые ложные области.

Forced-режим `enemy/loot/empty` обходит обычные веса и выключатели соответствующих типов. Поэтому его нельзя использовать для оценки нормального баланса.

### `debug_force_tier`

- `0` — фактический тир локации;
- `1`, `2`, `3` — принудительно использовать таблицы выбранного тира: map spot, радиусы, loot и enemy-профили.

Не выдавайте прогон с ненулевым значением за обычный тест конкретной локации.

### `debug_cleanup_current_sortie`

`true` запускает cleanup состояния текущей экспедиции на ближайшем update tick. Это диагностическая аварийная команда, а не обычный способ выхода. После срабатывания вручную верните `false`; иначе cleanup будет повторяться после следующих загрузок.

После любого forced-теста обязательный безопасный baseline:

```ini
debug_force_decoy_type = off
debug_force_tier = 0
debug_cleanup_current_sortie = false
```

Полностью перезапустите игру и убедитесь, что новый прогон не содержит строки активного `debug_force_decoy_type=...` и соответствует обычным весам из `decoy plan`.

## Live-log во время полевого теста

Правильный порядок: сначала watcher, затем X-Ray.

Из папки мода запустите:

```text
tools\watch_live_log.cmd
```

Либо из PowerShell:

```powershell
.\tools\watch_live_log.ps1
```

Дождитесь строки `Waiting for X-Ray and matching lines...`, затем запускайте игру. Watcher отслеживает реальные процессы X-Ray, а не MO2/launcher. После закрытия игры он дочитывает хвост 20 секунд и завершает с причиной сессии.

Строка `Session file` показывает авторитетный уникальный архив `aer-live-...log`. `latest.log` — только удобная best-effort копия; если она занята другой программой, уникальный session-файл всё равно продолжает записываться. `Ctrl+C` выполняет best-effort дочитывание и закрытие handles.

В установленной MO2-копии логи watcher по умолчанию сохраняются вне игры:

```text
Документы\Codex\Anomaly Expedition Rework\test-artifacts\live-logs
```

Произвольные пути можно задать явно:

```powershell
.\tools\watch_live_log.ps1 -LogPath 'E:\GRA2.5\Anomaly 1.5.3 up\appdata\logs\xray_maksi.log' -OutputDirectory 'D:\AER-logs'
```

## Минимальный набор ожидаемых строк

Для новой аномальной экспедиции в полном debug обычно нужны:

- `captured raid artifact` — перехвачен именно артефакт штатного рейдового спавна;
- `artifact spawn prevention accepted` — позиция прошла защитные проверки;
- `create type=artifact|enemy|loot|empty` — создана область;
- `decoy plan` и `decoy result` — план и итог ложных областей;
- `ambush squad created ... owned_by_rework=true` — создан собственный enemy squad;
- `close ... reason=actor_pickup|container_opened|all_dead_or_missing` — штатное закрытие;
- `transition pending`, затем `transition resolved same_level` при save/load или fast travel внутри того же уровня;
- `cleanup reason=confirmed_level_change` после настоящего выхода;
- `cleanup summary` — итоговые счётчики.

Для normal-прогона отдельно убедитесь, что нет строки активного `debug_force_decoy_type=...`, `[Anomaly Expedition Rework] ERROR` и FATAL. Внешние ошибки других скриптов сохраняйте в отчёте отдельно и не приписывайте этому моду без доказанной цепочки вызовов.

## Что приложить к отчёту об ошибке

1. Уникальный session-файл watcher либо полный актуальный `xray_*.log`.
2. Точный конфиг `rvm_sorties_rework.ltx` или его SHA-256.
3. Локацию, тип экспедиции, момент save/load/fast travel и последовательность действий.
4. Значения `debug_mode`, всех `debug_force_*`, `debug_cleanup_current_sortie`, `show_exact_*` и `artifact_rescue_actions`.
5. Скриншот карты, если проблема связана с кругом, tooltip или exact-маркером.
6. Версии MO2-мода, RVM, GRA Bolt, Arrival и PAW.

SHA-256 позволяет подтвердить, что тестировщики запускали один и тот же файл. В PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\gamedata\configs\plugins\rvm_sorties_rework.ltx'
```

## Финальный возврат к обычной игре

Перед обычным прогоном проверьте:

```ini
debug_mode = auto
debug_force_decoy_type = off
debug_force_tier = 0
debug_cleanup_current_sortie = false
show_exact_artifact_markers = false
show_exact_loot_markers = false
show_exact_enemy_markers = false
```

Не меняйте `artifact_rescue_actions` как часть обычной диагностики. До отдельного релизного решения безопасное значение — `false`. После восстановления настроек полностью перезапустите игру.
