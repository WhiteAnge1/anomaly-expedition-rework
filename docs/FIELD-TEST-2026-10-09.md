# Полевой тест: Поляна, 2026-10-09

Источники диагностики из рабочей папки основного агента:

- `test-artifacts/2026-10-09-pole-first-run/xray_maksi.log`;
- полный повторный прогон `test-artifacts/2026-10-09-pole-loot-debug-full-run/xray_maksi.log`.
- второй полевой прогон `test-artifacts/2026-10-09-pole-second-field-test/xray_maksi.log` и сохранённый live-tail пользователя.

## Что подтвердилось

- Перехвачен запуск `infected` на `y04_pole`.
- Захвачены ровно четыре ID рейдовых артефактов: `3084`, `6198`, `6200`, `6191`.
- Созданы четыре настоящие и две ложные loot-области; посторонние артефакты не маркировались.
- Три настоящие области закрылись с `reason=actor_pickup`, одна осталась активной.
- После сохранения/загрузки повторного создания областей не произошло.
- При смене уровня выполнена очистка шести областей.
- Все десять штатных попыток аномального тайника были подавлены, как требует `stash_mode = scouting`.
- Полный прогон подтвердил корректные закрытия `artifact` с `reason=actor_pickup` для anchors `26658`, `21448`, `21447` и loot `26671` с `reason=container_opened`. Эти исчезновения не являются ошибкой pickup.
- Четвёртая artifact-zone оставалась открытой до ошибочной ранней очистки на переходе.
- Второй прогон подтвердил сохранение artifact-zone `anchor=11764 linked=5848` после save/load и после PAW fast travel внутри `y04_pole`. В fast-travel пути `on_before_level_changing` не вызывался, но зоны не удалились и повторно не создавались.
- Подтверждены Debug UI `SendOutput`, красная точная иконка `paw_stash_red`, её исчезновение при debug-off, `container_opened` для loot-zone и обычный `actor_pickup` для artifact-zone.
- Military NPC подобрал связанный артефакт «Сердце»; при `remove_on_npc_pickup=false` область ожидаемо осталась. После снятия того же exact ID с трупа callback actor pickup не пришёл, поэтому область ошибочно не закрылась.
- Поздний прогон с принудительным `enemy` создал опасные области, но все четыре активации завершились `no safe spawn point`; замеченные тела и население имели `owned_by_rework=false` и относились к штатному RVM.
- Часть опасных областей могла активироваться уже на старте: прежние фиксированные 180 м были меньше суммы радиуса области и `ambush_trigger_padding` (197–210 м в наблюдениях).
- «Фонтан» логически находился внутри области (смещение около 58.3 м при радиусе 79 м), но с первого кадра отображался за нарисованным кругом — подтверждена ошибка UI-масштаба, а не мировой позиции.
- Для «Мяча» после загрузок подтверждено реальное перемещение под карту (Y около -46). «Булавка» находилась около начала мировых координат; отсутствие зелёного exact-marker пока требует повторной проверки после новой калибровки круга.
- Live watcher показал накопленные строки только после выхода из игры: `Get-Content -Wait` продолжал читать старый handle после пересоздания/обнуления xray log.

## Найденные проблемы и исправления

- Русская string table переведена из UTF-8 в Windows-1251, соответствующую фактическим таблицам сборки.
- Физический `raid_shelter_gag` заменён в роли постоянного map-якоря на PAW `script_zone`; действие «Перейти» больше не должно появляться.
- Невидимый голый `inventory_box` заменён связкой из штатной видимой модели `raid_small_stash_1..17` и наложенного inventory box.
- Отсутствующие во время выполнения `simk_card` и `artifact_container` удалены из таблиц наград; добавлена статическая проверка внешних секций и сохранена runtime-фильтрация через `ini_sys:section_exist`.
- Форматы `%.1f`, не поддерживаемые `printf` X-Ray, заменены безопасными строковыми значениями.
- Визуальный размер круга отделён от логического радиуса и ограничен при zoom.
- Для Поляны установлен `max_false_zones = 1`; все настоящие области сохраняются.
- `on_before_level_changing` больше не удаляет объекты немедленно. Он сохраняет pending-transition; на первом обновлении нового контекста same-level reload/fast travel восстанавливает spots, а настоящий уход подтверждает очистку.
- Debug-команды выводят короткий результат в Debug UI через защищённый `SendOutput` и дублируют его в журнал.
- Точный loot-marker заменён готовой красной иконкой тайника PAW.
- Круги переведены с фиксированных 44/56/68 px на ограниченное масштабирование баз 40/50/60 px в диапазоне `1.0..1.25`.
- Второй тест показал, что базы `40/50/60` при `1.25x` слишком мелкие. Новый пакет использует заметные `80/96/112 px`, bounded `1.0..1.35`, alpha `220` и более контрастный цвет.
- Добавлена независимая exact-ID проверка владения: actor inventory, online parent и server parent-chain. Она закрывает область с `reason=actor_owns_linked_artifact`, даже если callback потерян при corpse loot/trade; одна лишь одинаковая section никогда не используется.
- Добавлена fail-closed диагностика открытых артефактных областей: server/online existence и position, parent chain, расстояние/перепад высоты до anchor и ближайшей level vertex.
- Для дистанционного подбора артефакта NPC добавлен fail-closed fallback нового ID: он срабатывает лишь для единственной открытой зоны той же секции, когда старый exact ID уже исчез.
- Стартовый запрет опасной области теперь равен максимуму из базового значения и полного порога активации плюс 20 м. Поиск врагов имеет строгий и ослабленный безопасный режим, но всегда требует точку вне направления взгляда; видимый fallback запрещён.
- Круги перекалиброваны в `64/80/96 px`, `scale_max=2.25`: общий план компактнее, близкий zoom примерно на треть крупнее прежнего варианта.
- Live watcher больше не держит постоянный handle: он отслеживает пересоздание/обнуление файла и открывает актуальный путь каждые 250 мс.

## Следующий тест (отложен пользователем)

2. В конфиге временно установить `debug_force_decoy_type = enemy`, остальные debug-параметры оставить `0/false`, а `debug_log = true`.
3. Начать новую аномальную вылазку на Поляну. Старое сохранение можно загрузить только для проверки совместимости, но результат генерации оценивать на новой вылазке.
4. Убедиться, что строка `decoy plan` сообщает `cap=1` и создано не более одной ложной области сверх всех настоящих.
5. На карте проверить оба крайних zoom: linked artifact должен быть внутри нарисованной окружности уже с первого кадра, а обзорный круг не должен разрастаться по старому пределу `3x`.
6. Правой кнопкой по кругу проверить отсутствие «Перейти» и корректную постановку PAW-маршрута на центр.
7. Найти опасную ложную область: она не должна активироваться на старте. При подходе ожидаются `ambush entity ... owned_by_rework=true` и `ambush ... spawned=...`; допустим безопасный `fallback=relaxed_out_of_view`, но не появление противников перед камерой.
8. Сделать сохранение/загрузку или fast travel внутри Поляны: оставшаяся зона должна сохраниться, без новых `create`; ожидается `transition resolved same_level`.
9. Выйти с Поляны: ожидается `cleanup reason=confirmed_level_change`, без оставшихся служебных объектов.
10. В Debug UI (не в консоли `~`) проверить подтверждения `rvm_rework_debug_off/on/auto` и краткий ответ `rvm_rework_census`.
11. Проверить лог на отсутствие `config section missing`, ошибок форматирования и Lua/X-Ray ошибок с префиксом мода.
12. Вернуть `debug_force_decoy_type = off` после теста.
13. Дать NPC подобрать linked artifact при `remove_on_npc_pickup=false`, убить его и снять именно этот предмет с трупа. Область должна сохраниться у NPC, затем закрыться с `reason=actor_owns_linked_artifact` у игрока.
14. Для подозрительного пропавшего артефакта сохранить строки `artifact diagnostic`: отрицательный `vertex_dy`/`anchor_dy` и позиции позволят проверить гипотезу провала под карту без вмешательства в spawn.
15. После enemy-проверки отдельным рейдом вернуть `debug_force_decoy_type = loot` и сохранить полную строку `target/created/ordinary/valuable_quota/valuable_actual/valuable_sections/rare`; `valuable_actual` не должен превышать quota, а T1 valuable должны принадлежать только списку из трёх секций.
16. В debug-on проверить зелёную stash-иконку на каждом exact linked artifact и красную squad-точку на каждом живом mod-owned enemy. После debug-off должны остаться круги, но исчезнуть все exact-маркеры; после debug-on они восстанавливаются.
17. Убить врагов по одному: соответствующая красная точка исчезает на следующем update, остальные остаются. После same-level save/load точки живых целей восстанавливаются без дублей; `owned_by_rework=false` население не маркируется.

## Дополнительное расследование населения

В сохранённом логе первого прогона отсутствуют `create type=enemy`, `ambush entity` и `ambush spawned`, поэтому замеченные мутанты не были созданы Anomaly Expedition Rework. При этом журнал содержит несколько штатных наборов населения, два из которых явно помечены RVM-доспавном:

- около строки 14010 — три flesh без соседней строки нашего мода или явного тега доспавна;
- строка 14307 — штатный mutant-доспавн, после которого зарегистрированы четыре flesh и два boar;
- строка 14614 — ещё один штатный mutant-доспавн, после которого зарегистрированы три boar.

Для `y04_pole/infected` штатный `raid_dospawn_dungeons` целится не в число отдельных мутантов, а в число squad: `number_squads = 9`, динамический `fill_ratio_squads = 50..120%`, повторная проверка примерно каждые 90 секунд и `mutant_spawn_chance = 105`. Одна mutant-squad может содержать несколько особей. Поэтому 14 убитых мутантов необычны субъективно, но допустимы самой конфигурацией: целевой диапазон достигает примерно 4.5–10.8 squad, а не 4.5–10.8 особей.

Вывод первого отчёта «нет признака повторного доспавна» опровергнут полным live-tail. Он подтвердил штатные повторные вызовы RVM примерно по интервалу `time_between_dospawns = 90`:

- `sortie_start`: 4 squad, 3 stalker, 12 mutant;
- первый `raid_start_spawn mutant [2]`: добавлены flesh и lurker, census вырос до 14 мутантов;
- следующий `raid_start_spawn mutant [2]`: добавлены flesh и cat, в соответствующем снимке оставалось 7 мутантов;
- далее census снизился `6 -> 4 -> 0` и до `raid_timer=290` оставался нулевым.

Все эти squad имеют `owned_by_rework=false`: их создаёт штатный `raid_dospawn_dungeons`, не этот мод. Баланс в текущем пакете намеренно не меняется.

Решение пользователя окончательное: авторский баланс RVM имеет приоритет; initial spawn и repeated dospawn не меняются. Второй контрольный рейд подтвердил нормальный интервал: timer `1500`, ручные census `1474/1456/1436/1429`, затем две squad около `1408`, то есть примерно через штатные 90 секунд. В save/load прогоне spawn около `1411`, а после load обнаружена одна новая squad при `1390`; это остаётся наблюдением для следующего теста same-level load/fast travel, но не основанием для патча.

## Реализованный loot quality policy

В установленной тестовой копии `debug_force_decoy_type=loot` пока принудителен; нормальный шанс типа loot равен `10/(20+10+10)=25%` среди ложных зон. Обычный target distinct count сохраняется равномерным `1..6`. Исправлено только качество наполнения: старый алгоритм почти равноправно выбирал `utility/modules` (`45/55`) и мог одновременно выдать все дорогие T1-позиции.

Для старого алгоритма вероятность всех трёх T1 valuable имела только доказанный нижний предел `21.67%`: medicine + target 6 давали `70% × 1/6 = 11.67%`, а отсутствие medicine + target 5 или 6 — ещё `30% × 2/6 = 10%`. Другие случайные последовательности только повышали итог. Поэтому богатый field-test chest не был jackpot порядка `0.05%`.

Новый алгоритм использует явные tier-aware `loot_valuable`, а не ненадёжную runtime-классификацию по `cost`. Для T1 valuable — строго `itm_ammokit`, `af_iam`, `lead_box`; `detector_simple`, `itm_sleepbag` и medicine входят в low-value candidates. T2/T3 имеют отдельные редактируемые списки, но наследуют те же безопасные staged chances.

Квота valuable бросается независимо для каждого loot-контейнера:

- `P(quota >= 1) = 35%`;
- `P(quota >= 2 | quota >= 1) = 10%`;
- `P(quota >= 3 | quota >= 2) = 1.5%`.

Отсюда точные вероятности квоты: `P0=65%`, `P1=31.5%`, `P2=3.4475%`, `P3=0.0525%`. При обычном шансе loot-zone на Поляне верхняя вероятность тройной квоты среди всех ложных зон/рейдов равна `25% × 0.0525% = 0.013125%`. Фактический `valuable_actual` может быть только меньше квоты из-за target capacity или исчерпания distinct pool и никогда не может её превысить.

Medicine-roll по-прежнему предпочитает первый медицинский слот. Затем выдаются valuable до квоты/capacity, остаток target заполняется distinct low-value кандидатами. Если дешёвый пул исчерпан, контейнер завершается раньше target и не добивается дорогим предметом. `rare_slot_chance=4%` и `rare_artifact_chance=70%` остаются независимым jackpot и в valuable quota не входят.

Лог теперь содержит `target`, `created`, `ordinary`, `valuable_quota`, `valuable_actual`, точные `valuable_sections`, `rare` и `rare_artifact`. `tools/test_loot_policy.ps1` проверяет формулу, 200000 детерминированных выборок и отсутствие `actual > quota`.

## Внешние сообщения полного лога

- В полном прогоне нет `ERROR` или `FATAL` с префиксом `[Anomaly Expedition Rework]`.
- `typing1.ogg`, `bone_position` для lurker, трассы `xrs_facer`/`xr_corpse_detection`, а также ранние ошибки чужих скриптов не исходят из файлов мода и в этом пакете не патчатся.
- Один PAW debug fast-travel отправил игрока под карту. Наши anchors создаются только из проверенного `level.vertex_id` и нормализуются через `level.vertex_position`; мод не телепортирует actor. Без доказательства связи общий баг PAW не присваивается этому моду.
