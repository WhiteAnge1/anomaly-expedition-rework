# Roadmap до публичного релиза

Текущее состояние: основная механика, normal T1 smoke, T1/T2/T3 forced loot/empty, enemy squad lifecycle, exact-маркеры, save/load, cleanup, artifact spawn guard и три rescue-класса имеют полевые либо исполняемые доказательства. Следующая цель — обычная Тёмная лощина с штатным числом артефактов и без forced/debug-подсказок.

## 1. Закрыть оставшиеся полевые проверки

1. Один обычный debug-off прогон T2 в Тёмной лощине: подтвердить штатные `8` артефактов/истинных областей против `4` на Поляне, индивидуальные радиусы `150..240 м`, визуально оценить loot `offset <= radius/5` и поведение proximity-засады только если enemy естественно выбран.
2. Один обычный debug-off прогон T3 в Мёртвом городе: подтвердить штатные `6` артефактов/истинных областей, индивидуальные радиусы `140..220 м`, визуально оценить loot `offset <= radius/10`; enemy squad там, как и на T1, создаётся сразу при старте.
3. Один финальный release-candidate smoke с normal config: существующее сохранение, новая вылазка, выход и повторная загрузка убежища; forced/debug-параметры должны оставаться выключенными.

Новые forced-loot/forced-empty и повтор T1 не требуются. Пользовательские artifact/loot/enemy exact-маркеры и их reload/pickup/open/commander-death lifecycle приняты.

Количество берётся не из тира: это штатная матрица активного `GRA Bolt` — `y04_pole=4`, `k01_darkscape=8`, `l09_deadcity=6` (дополнительные штатные T2 `l06_rostok=3`, `l08_yantar=3` текущим профилем реворка не поддерживаются). Поэтому обычные прогоны обязаны проверять именно локационные числа, а не только T1/T2/T3.

## 2. Решить публичный default artifact rescue

Перед заморозкой конфига пользователь выбирает один из вариантов:

- оставить `artifact_rescue_actions = false` для первого публичного alpha-релиза — наиболее консервативный вариант;
- включить `true`, опираясь на принятые rolling/underground/origin same-ID held-тесты.

После решения меняется только версионируемый default и связанное описание; лабораторные debug gates остаются выключенными.

Отдельное решение уже принято: координатный rescue по условным границам игровой карты не разрабатывается. Границы доступны только как хрупкие локационные эвристики и могут перемещать корректный предмет. Редкий известный случай, когда артефакт физически оказался за доступной частью карты, но всё ещё находится внутри связанного круга, rescue не запускает. Если предмет выйдет за круг дальше порога `linked radius + 5 м` и останется там 15 секунд, его уже классифицирует обычный rolling-path.

## 3. Заморозить release candidate

- выбрать следующую версию и обновить её во всех runtime/FOMOD/meta/docs местах;
- зафиксировать normal config без forced-параметров;
- выполнить полный `static_check`, Lua 5.1/LuaJIT, XML/CP1251, watcher self-test и `git diff --check`;
- сверить source и установленную MO2-копию по SHA-256.

После заморозки допускаются только blocker-fixes с повторной проверкой затронутого сценария.

## 4. Завершить документацию

- краткое описание для обычного игрока: что меняется в вылазках и что остаётся штатным;
- подробное описание для опытного игрока: типы областей, награды, enemy/loot/empty, артефакты/классы/мутации, настройки;
- установка через MO2, приоритеты, обновление поверх alpha, удаление и возврат к исходному поведению;
- совместимость и требования к RVM/GRA Bolt/Arrival/PAW;
- debug-guide, известные ограничения, troubleshooting и changelog.

## 5. Проверить установку и обновление

На копии профиля MO2 проверить два пути:

1. чистая установка архива в новый мод с ожидаемым именем и версией;
2. обновление с текущей `0.2.1-alpha` без потери пользовательского конфига и без старых runtime-файлов.

После каждого пути: запуск существующего убежища, новая вылазка, отсутствие FATAL/ошибок мода, корректное отключение/удаление.

## 6. Собрать и опубликовать

- собрать воспроизводимый MO2/FOMOD-архив;
- записать SHA-256 архива и перечень файлов;
- создать Git tag и GitHub release с changelog, инструкцией и исходниками;
- после отдельной отмашки пользователя загрузить тот же проверенный архив и инструкции на Google Drive;
- проверить обе ссылки и совпадение SHA-256 скачанных файлов.

Публичный релиз считается готовым только после полевых пунктов 1, решения из пункта 2 и успешной clean-install/upgrade проверки.
