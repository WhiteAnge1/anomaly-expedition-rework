# Anomaly Expedition Rework by White_Angel

Текущая публичная версия: **0.3.0-rc7**. Это открытый MO2-мод для проверенной сборки GRA 2.5 с активным `GRA Bolt`: он перерабатывает аномальные вылазки, не изменяя файлы исходных модов.

В исходной аномальной вылазке RVM нет отдельных точных меток рейдовых артефактов: игрок ищет их по всей локации. Реворк добавляет приблизительные области поиска со смещённым центром, но по умолчанию по-прежнему не раскрывает точную позицию артефакта. Точная наводка на исходный тайник — другая механика и не является подсказкой для поиска рейдовых артефактов.

## Установка

1. Требуется **Anomaly MCM 1.7.2** из сборки (или совместимая версия с API `on_mcm_load`/`ui_mcm.get`). Скачать версионный архив из GitHub и установить через MO2 как новый отдельный мод. Не объединять его папку со старой или разработческой копией.
2. В окне FOMOD нажать обычную кнопку **«Установить»**. Штатная кнопка MO2 **«Вручную»** для стандартной установки не нужна — её не следует нажимать. Корень архива уже подготовлен правильно: MO2 автоматически распознаёт каталоги `gamedata` и `fomod`.
3. Оставить предложенное FOMOD имя `[Геймплей] Anomaly Expedition Rework by White_Angel v0.3.0-rc7`: категория и версия сразу видны в списке MO2.
4. FOMOD устанавливает один проверенный профиль **«Рекомендуемая базовая конфигурация MCM»**. После запуска игры открыть `Настройки → MCM → Переработка аномальных вылазок`: там находятся поддерживаемые игровые параметры.
5. Поставить его **выше по приоритету конфликтов** относительно `GRA Bolt`, системы аномалий Arrival и PAW. Мод не заменяет их Lua-файлы или `map_spots.xml`; для map spot используется DXML.
6. Если игра была запущена во время установки, полностью выйти из неё на рабочий стол и запустить снова. Начинать новую игру или новое прохождение не требуется. Мод применяется при следующем входе на локацию вылазки. При запуске игры с глобальным `-dbg`/`-dbgdev` диагностика мода включится автоматически.
7. Приоритет значений: валидное значение MCM → `gamedata/configs/plugins/rvm_sorties_rework.ltx` → безопасный runtime-default. Отсутствующий или сломанный MCM не мешает загрузке: мод продолжает работу по LTX. Debug/laboratory-настройки намеренно остаются только в LTX.

При обновлении установить новую версию отдельной записью MO2 и отключить старую. MCM Reset/Defaults восстанавливает тот же публичный baseline, что LTX fallback. Старые ручные LTX-значения для настроек, представленных в MCM, имеют меньший приоритет; debug/laboratory-значения переносятся вручную только при наличии migration note.

Все игровые MCM-настройки фиксируются одним снимком при начале новой вылазки и сохраняются вместе с ней. Изменения во время уже начатой вылазки не перестраивают её частично и вступят в силу на следующей новой вылазке. Для установки или обновления скриптов нужен полный перезапуск игры.

`0.3.0-rc7` создаёт якоря приблизительных зон как собственные объекты AER, не регистрируя их во внутреннем реестре временных `script_zone` PAW. Поэтому автоматическое закрытие или ручная отмена маршрутной метки PAW не должны удалять открытую зону AER. Потерянный якорь открытой зоны восстанавливается без повторного создания артефакта, тайника или отряда; открытые зоны из сохранений RC6 мигрируют тем же путём. Закрытые зоны не восстанавливаются.

Принятый в RC6 scripted self-target для принадлежащих моду засад сохранён без изменений. Это не `__lock`: нормальное online/offline-переключение и online monster AI остаются штатными. Мод не телепортирует NPC и не записывает им position/vertex.

Уже полученный до установки маршрутный лист можно использовать: он задаёт тип и локацию вылазки, а задачи, аномалии и артефакты создаются после перехода на локацию. При входе использованный лист расходуется. Если обходными средствами загружено сохранение уже внутри ранее начатой вылазки, мод не подключается задним числом к созданному до его запуска контенту — вернитесь в убежище и начните следующую вылазку.

Удаление/отключение мода возвращает исходное поведение: единственные LTX-переопределения относятся к описаниям маршрутных листов, а вся механика подключается отдельными скриптами.

## Что меняется в игре

- перехват только `raid_anomalys.spawn_artefact_in_zone`; обычные артефакты и артефакты системы аномалий Arrival не сканируются и не маркируются;
- отдельный невидимый якорь для центра каждой настоящей области; положение артефакта не передаётся карте или PAW;
- настоящие артефактные области могут перекрываться: близкий штатный спавн нескольких артефактов не должен лишать часть из них круга; `zone_separation_min` продолжает разносить ложные области;
- количество настоящих артефактов бросается один раз при создании новой вылазки и сохраняется: Поляна `3/4/5 = 35/60/5%`, Тёмная лощина `5/6/7/8/9 = 5/20/47/26/2%`, Мёртвый город `4/5/6/7 = 11/80/7/2%`; средние `3.7/7/5`, а некорректный профиль возвращает stock `4/8/6`;
- настоящий артефакт сохраняет штатное семейство аномалии, но рекомендуемый профиль `weighted` отдельно выбирает качество и затем одну из всех 223 базовых секций семейства: T1 `45/45/10/0/0`, T2 `10/32/43/15/0`, T3 `2/8/43/45/2%` для `junk/low/medium/high/unique`; повторы между независимыми бросками разрешены;
- локальная таблица GRA Bolt подменяется только синхронно на время одного штатного вызова и обязательно восстанавливается; неверные веса, состав каталога, отсутствующая секция или недоступный hook целиком возвращают исходный stock-selector с явной диагностикой;
- отдельный расчёт ложных областей: Поляна всегда 1, Тёмная лощина получает 2/3/4 области с весами `33/34/33`, Мёртвый город 1/2/3 с вероятностями `20/60/20`; их типы имеют веса `50/25/25` для `enemy/loot/empty`;
- выбранный тип ложной области не перебрасывается при ошибке размещения: журнал явно сообщает о неудаче, а более безопасный тип не подменяет исходный результат;
- типы `enemy`, `loot`, `empty`, внешне использующие один и тот же map spot;
- безопасная задержка до фиксации фактической позиции actor;
- мутантская засада как единый настоящий squad из точного тематического пресета: сначала категория `частая/редкая/суперредкая` с весами `4:2:1`, затем равновероятный набор внутри категории; неполный отряд полностью откатывается;
- каскад размещения сохраняет level vertex и безопасную геометрию: Поляна/Мёртвый город начинают внутри круга; Тёмная лощина использует расширенный скрытый поиск, затем видимый fallback сначала внутри круга и только потом немного снаружи;
- видимый и открываемый контейнер в визуальной центральной части круга: предел `radius/3` в T1, `radius/5` в T2 и `radius/10` в более компактном T3-круге; наполнение идёт этапами medicine → valuable → ordinary → rare, с лимитами `6/7/8` и независимым редким jackpot;
- medicine делает два последовательных броска, ordinary гарантирует хотя бы один предмет и допускает повторы, осколки имеют тир-зависимое количество, valuable использует цепочку `35% → 10% → 1.5%` без повторов (кроме `lead_box` на T3);
- редкий артефакт выбирается из актуальных таблиц РВМ: Поляна — весь мусор и T1, Тёмная лощина — T1 и T2, Мёртвый город — T2 и T3;
- созданный в контейнере артефакт передаётся штатной сохраняемой очереди `raid_artefacts`, поэтому получает родной случайный класс и мутации РВМ;
- `stash_mode = anomaly/scouting/disabled` без одновременного создания одного набора тайников;
- удаление настоящей области при подборе игроком и опционально NPC; если RVM заменяет подобранный NPC мировой ID новым инвентарным ID, однозначная section-lineage сохраняется через save/load и позволяет позднее закрыть исходную область при получении предмета игроком;
- сохранение состояния и восстановление отсутствующих map spots после загрузки или fast travel внутри той же локации;
- preventive guard второго RVM vertex/create с bounded retry, сохраняющий штатный выбор section и очередь классов/мутаций; после нормализации X-Ray binder/first-update ждёт готовности physics shell, затем атомарно поднимает exact client object через экспортированный `force_set_position(pos, true)` на настраиваемые `0.5..3.0 м` (по умолчанию `1.0`) над доказанной static-ray поверхностью, проверяет позицию и фиксирует shell до подбора — без сравнения `game_object` userdata, ALife teleport, пересоздания, suspect-delay и action limits;
- отложенная очистка якорей, созданных существ, контейнеров и служебного состояния только после подтверждённого ухода с локации;
- компактный обычный журнал с префиксом `[Anomaly Expedition Rework]`; координаты, ID, census и периодическая диагностика появляются только в debug, а ошибки пишутся всегда.

## Необязательные точные метки

Обычный замысел мода — искать цель внутри приблизительной области. Для более казуального прохождения точные метки независимо включаются во вкладке MCM `Точные метки` (LTX остаётся fallback):

- `show_exact_artifact_markers = true` — зелёные метки связанных рейдовых артефактов;
- `show_exact_loot_markers = true` — красная stash-метка контейнера с добычей;
- `show_exact_enemy_markers = true` — одна красная точка на игровом командире созданного модом отряда; после его смерти точка переносится на нового командира.

По умолчанию все три значения `false`. В пользовательском режиме это строго icon-only: без подписи, названия, ID и координат. Обычный содержательный tooltip приблизительного круга сохраняется всегда. Exact-иконки получают повышенный `location_level=20`; отдельной XML hit-area движок не предоставляет, поэтому иконки слегка увеличены без смещения точной позиции. Они не включают журнал или census. Изменения применяются со следующей новой вылазки. Полный справочник: [`docs/CONFIG.md`](docs/CONFIG.md).

## Диагностика и поддержка

`debug_mode = auto` следует глобальным `DEV_DEBUG`/`DEV_DEBUG_DEV`; при публичных значениях по умолчанию диагностические подписи и точные маркеры выключены. Значения `on` и `off` в конфиге принудительно переопределяют auto. Старый `debug_log` используется только как fallback, если `debug_mode` отсутствует.

Команды доступны в окне **Debug UI** от debug launcher, а не в обычной консоли движка по клавише `~`:

- `rvm_rework_debug_on`, `rvm_rework_debug_off`, `rvm_rework_debug_auto` — надёжные команды без аргументов;
- `rvm_rework_debug auto|on|off` — единая форма, если конкретный launcher передаёт аргументы callback;
- `rvm_rework_census` — ручной снимок рейдовых squad и созданных модом существ.

Команды переключения выводят в Debug UI выбранный и фактически действующий режим. `rvm_rework_census` выводит туда краткий итог `squads/stalkers/mutants`, а полный состав остаётся в `xray_*.log`. Если конкретная версия UI не передаст объект окна в callback, сообщение всё равно попадёт в лог через `printf`.

В debug-режиме открытые артефактные области также пишут exact-ID диагностику объекта: server/online existence, parent chain, позиции и перепад высоты до ближайшей level vertex. Новый proactive lifecycle пишет `artifact proactive target/online/hold attempt/held/save/rehydrate/release`; успех `held` публикуется только после свежей проверки current shell относительно target, static surface и vertex. Старые alpha-записи без доказанного target остаются observe-only; их `captured/first_suspect/confirmed` не запускают рискованный rescue. Лабораторный legacy `debug_teleport` сохранён только для прежних исследовательских сценариев. Если callback пропущен при снятии связанного артефакта с трупа, периодическая exact-ID проверка закроет область только после фактического появления этого объекта у актёра.

Runtime-переключатель меняет только журнал, технические tooltip и диагностические exact-маркеры. Генерация областей, наград и противников не отключается. Override сбрасывается при смене уровня или полном перезапуске. При включённом полном debug все три exact-маркера показываются независимо от пользовательских значений `show_exact_*`.

В debug-режиме обычное описание каждого круга сохраняется, а ниже показываются `kind`, anchor ID, логический радиус и связанный ID. Дополнительно linked artifact получает зелёную exact-иконку, loot-контейнер — красную, а командир созданного модом отряда — красную squad-иконку. У exact-маркеров есть технические tooltip только в debug. После debug-off отдельно включённые пользовательские метки показывают лишь локализованную нетехническую подсказку без ID, координат и содержимого.

Для live-наблюдения сначала запустите из папки мода `tools\watch_live_log.cmd`, дождитесь `Waiting for X-Ray and matching lines...`, и только затем запускайте X-Ray. До первого обнаружения игры watcher не закрывается. Он следит только за настоящими исполняемыми файлами X-Ray текущей сборки (`AnomalyDX8/9/10/11`, их AVX-варианты и `VerifiedDX11`) в игровом `bin`, поэтому запуск или закрытие MO2/launcher не считается игровой сессией. После закрытия X-Ray watcher ещё 20 секунд забирает хвост лога и закрывается сам. Уникальный `aer-live-...log` является главным архивом; `latest.log` обновляется best-effort и при чужой блокировке выдаёт одно предупреждение, но не останавливает наблюдение. При `Ctrl+C` watcher также пытается дочитать хвост и корректно закрыть все handles.

Путь сохранения всегда печатается строкой `Session file`. При запуске из репозитория это `test-artifacts\live-logs` внутри проекта (каталог исключён из Git). Установленная MO2-копия сохраняет вне каталога игры — в `Документы\Codex\Anomaly Expedition Rework\test-artifacts\live-logs`. Однострочный вариант PowerShell с собственными путями:

```powershell
.\tools\watch_live_log.ps1 -LogPath 'E:\GRA2.5\Anomaly 1.5.3 up\appdata\logs\xray_maksi.log' -OutputDirectory 'D:\AER-logs'
```

Для другой установки можно явно задать `-GameBinPath` и один или несколько `-ProcessNames`; штатный default уже соответствует этой GRA 2.5. Параметр `-ShutdownGraceSeconds` существует прежде всего для автоматических тестов: обычное значение `20` менять не требуется.

Исходный код и история версий: <https://github.com/WhiteAnge1/anomaly-expedition-rework>.

Полное руководство по debug-режиму, forced-тестам, census и live-log: [`docs/DEBUG-GUIDE.md`](docs/DEBUG-GUIDE.md).

Перед обращением приложите версию мода и сборки, профиль FOMOD, название локации/тип вылазки, шаги воспроизведения, сохранение до ошибки и конец `xray_*.log`. Готовый шаблон: [`docs/SUPPORT.md`](docs/SUPPORT.md).

## Известные ограничения

- X-Ray задаёт размер map spot в UI-пикселях, а не в мировых метрах. Поэтому круг — символическая приблизительная область. Базы T1/T2/T3 теперь `32/60/48 px`, у всех сохранена динамика zoom `1.0..4.5`: после полевого теста увеличен только абсолютный T2-размер примерно в 1.5 раза. Фактическая логика размещения продолжает использовать метры из конфига.
- Два exact-marker артефактов в одной точке X/Z неизбежно рисуются друг поверх друга: доступный Lua API умеет добавить/удалить spot и задать tooltip, но не даёт надёжной кластеризации или порядка слоёв. Мод не сдвигает «точные» метки с реальных объектов; в debug-журнал один раз за сессию пишется `exact artifact marker overlap ... exact positions preserved` для пар ближе 2 м.
- Для proximity-засады Тёмной лощины проверка «не перед глазами» использует реальное направление камеры и дистанцию. Скрытые ступени получили втрое больше кандидатов и low-discrepancy покрытие углов/дистанций/nav-вершин; если они исчерпаны, видимый fallback сначала пробуется внутри круга и лишь затем снаружи. Надёжного Lua raycast до произвольной точки всё ещё нет.
- Production policies касаются строгого `origin_mismatch`, подтверждённого `rolling` и настоящего inside-radius vertical `underground`: один same-ID rescue проходит три fresh snapshots, post-teleport reacquire и held до ownership/pickup либо lifecycle safeguard. Все три пути полево приняты, включая левитирующую `af_night_star#1407` и два независимых legacy world-origin ID `#6910/#6930`. Origin требует точную запись штатного реестра RVM, исходный field LVID и доказанное `server.online=true`, вызывает штатный `server:switch_offline()` и bounded ждёт исчезновения exact client shell. C++-метод имеет `void`-семантику, поэтому Lua `nil` считается нормальным возвратом, но не доказательством успеха: успех подтверждают только исчезновение shell и заново полученная exact server identity, не сообщающая явное `online=true`. Лишь затем переносится тот же ID и перестраивается жёлтая область. Принятый прогон дал для каждого ID ровно один dispatch, три `origin_exact_field` проверки, новый anchor, 30-секундный held monitor и штатный pickup/closed без duplicate-ID. Recreate, release, `apply_force` и section fallback запрещены; общий master по-прежнему имеет безопасный default `false`.
- Если центр построить не удалось, первое `ERROR` и минутные summary содержат исходную позицию, `near_origin`, число проходов/попыток и причины `invalid_vertex`, `post_snap_limit`, `separation`, `anchor_failure`. Это только диагностика: предмет не перемещается и не подменяется.
- Засады намеренно состоят только из мутантов: люди/NPC не используются из-за их штатной невосприимчивости к аномалиям.
- Открытый контейнер не удаляется немедленно: callback снимает область и якорь, а сам box удаляется при выходе. Это предотвращает инвалидирование открытого окна инвентаря.
- На Поляне (`y04_pole`) южный склон способен физикой X-Ray скатить уже корректно размещённый артефакт далеко от исходной области. Классификатор подтверждает выход за `linked radius + 5 м` в течение 15 секунд; production rescue реализован, но общий action gate оставлен выключенным до широкого smoke-test.
- Мод намеренно не пытается определять доступную часть каждой карты по координатным границам: универсальной надёжной Lua-границы нет, а ручные bounding boxes хрупки. Поэтому в редком случае предмет может физически оказаться за доступной частью карты, но всё ещё внутри своего связанного круга — тогда rescue не сработает. После устойчивого выхода дальше `linked radius + 5 м` применяется обычная rolling-классификация (если общий action gate включён).
- Центры областей используют собственные невидимые `script_zone` AER и не регистрируются как временные объекты PAW. RC7 восстанавливает потерянный anchor открытой зоны без повторного создания её содержимого; автоматическое закрытие, ручная отмена и перенос PAW waypoint приняты полевым тестом. Для выбора безопасной случайной координаты РВМ кратковременно используется его внутренний размещатель, но map spot и маршрут PAW никогда не привязываются к служебному `raid_shelter_gag`.
- Обычные предметы и осколки выбираются с указанными в конфиге весами; на старших тирах доля осколков растёт. Вероятность редкого слота и доля артефактов в нём настраиваются отдельно; внутри разрешённого артефактного пула выбор равновероятный.
- Известные незакрытые вопросы отслеживаются отдельно: [подтормаживание при появлении T2-засады](https://github.com/WhiteAnge1/anomaly-expedition-rework/issues/3) и [безопасная, но медленная перезагрузка локации при debug-переходе к метке артефакта](https://github.com/WhiteAnge1/anomaly-expedition-rework/issues/5). Они не являются регрессиями RC7 PAW anchor fix.

## Быстрая проверка установки

1. Запустить игру с глобальным debug либо временно выставить `debug_mode = on`.
2. Получить и использовать маршрутный лист аномальной экспедиции (`infected`).
3. В логе найти `captured raid artifact`, затем строки `create type=...`.
4. Проверить, что ID настоящих областей совпадают только с ID из захвата функции рейдового спавна.
5. На карте нажать правой кнопкой по центру круга и поставить PAW-маршрут: он должен указывать на независимый якорь.
6. Поднять артефакт — соответствующая область должна исчезнуть.
7. Сохраниться, загрузиться или сделать fast travel внутри той же локации — число `create` не должно увеличиться, незакрытые zones и spots сохраняются; в логе ожидается `transition resolved same_level`.
8. Выйти с локации — в логе должна появиться строка `cleanup reason=confirmed_level_change`, а служебные объекты должны быть освобождены.
9. Повторить для разведывательной вылазки: исходные точки разведки и разведданные сохраняются, дополнительно появляется один исходный тайник.
10. Для проверки редких наград временно поднять `rare_slot_chance` и `rare_artifact_chance` до 100, затем проверить разрешённые тиры, класс, мутации и сохранение/загрузку до открытия контейнера. После теста вернуть значения 4 и 70.
11. Для true-field weighted-пула ориентироваться на строки `artifact_pool raid=...`: они показывают тир, семейство, качество, base-section, бросок, веса и fallback. Внешний wrapper Rojok остаётся штатным, поэтому созданный exact ID должен получить обычные класс/мутацию и пережить save/load.

Для принудительных тестов используйте `debug_force_decoy_type`, `debug_force_tier` и `debug_cleanup_current_sortie` в конфиге. После проверки обязательно верните их в `off`, `0`, `false`.

Подробности исследования: `docs/RESEARCH.md`. Матрица приёмки: `docs/TESTING.md`.

## Обновление, откат и удаление

- RC7 устанавливается новой отдельной записью MO2; прежнюю RC/alpha-запись нужно отключить, а не объединять с новой.
- FOMOD не копирует и не объединяет старый LTX. Поддерживаемые пользовательские значения переносите вручную по [`docs/CONFIG.md`](docs/CONFIG.md); forced/debug-параметры оставляйте в публичных defaults, если они не нужны для отдельного теста.
- После установки, обновления или отката полностью перезапустите игру. Новая игра не нужна: изменения применятся при следующем входе на локацию новой вылазки.
- Уже открытая RC6-зона совместима с RC7: PAW-owned anchor мигрирует без повторного spawn содержимого. Старые уже перемещённые RC5 enemy squad намеренно не телепортируются обратно.
- Для отката отключите RC7 и включите прежнюю отдельную запись. Полное отключение/удаление AER возвращает поведение исходных модов; загрузку сохранения с активной незавершённой зоной лучше выполнять с той версией AER, которая её создала.

## Проверка целостности

Рядом с ZIP в GitHub Release публикуется файл `.sha256`. Проверка в PowerShell:

```powershell
(Get-FileHash -Algorithm SHA256 -LiteralPath '.\Anomaly-Expedition-Rework-0.3.0-rc7.zip').Hash
```

Результат должен совпасть со строкой в `Anomaly-Expedition-Rework-0.3.0-rc7.zip.sha256`. Тег `v0.3.0-rc7`, исходный commit и release assets относятся к одной проверенной сборке.
